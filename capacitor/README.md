# Capacitor example

The [Vite example](../vite)'s order confirmation page, wrapped with Capacitor for iOS and Android.
Accepted offers open in an in-app browser through `@capacitor/browser` (SFSafariViewController on iOS, Custom Tabs on Android):

```jsx
<UptickFlow integrationId={…} order_id={order.id} openUrl={(url) => Browser.open({ url })} />
```

The SDK hands the URL to `openUrl` instead of calling `window.open`, so the flow moves on to the next offer while the in-app browser is open.

## Requirements

- Xcode for iOS, with a simulator
- Android Studio for Android, with an emulator. The command line build uses Android Studio's bundled JDK: `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.

## Run against production

```
cp .env.example .env.local   # set VITE_UPTICK_INTEGRATION_ID
npm install
npm run ios       # or: npm run android
```

Each script builds the web app, copies it into the native project with `cap sync`, and asks which simulator or emulator to launch.
`.env.local` is read at build time, so run the script again after changing it.
`npm run dev` serves the same page in a desktop browser, where `Browser.open` falls back to a new tab.

## Run against a local API

Set `VITE_UPTICK_HOST=uptick.test` in `.env.local` and use the public id of an integration in your local database.
The app then talks to `app.uptick.test` and `api.uptick.test`, so the device needs to resolve those names and trust the local development certificate.

- **iOS simulator** resolves the host machine's names. Trust the local development CA once with `xcrun simctl keychain booted add-root-cert <ca.pem>`.
- **Android emulator** does not see the host's resolver rules or user CAs. Route its traffic through the host's resolver and trust the development CA the same way as the React Native demo (`uptick-ads/uptick-react-native-web`, "Testing against a local Uptick API"), with a network security config added to `android/app/src/main/res/xml` that trusts user CAs.

## Native projects

`ios/` and `android/` are generated by `npx cap add ios` and `npx cap add android` and are unchanged apart from the app id and name in `capacitor.config.json`.
`cap sync` copies the web build into them; the copied files are ignored by git.
